Nothing underneath

No borrowed engine, no system web view. hop lays out and paints every page itself.

HTML The WHATWG tokenizer and tree construction, with script-aware parsing.
CSS Selectors, cascade, inheritance and computed style.
Layout Block, inline, flex, grid, tables, floats and positioned boxes.
JavaScript Its own parser, bytecode compiler, VM and garbage-collected heap.
WebAssembly An interpreter and a JIT, both written for hop.
Networking Fetch, CORS, HTTP/1.1 and HTTP/2, WebSocket, cookies and cache.
Rendering Vector paths, anti-aliasing and compositing, rasterized in software.
Text & fonts Line breaking, bidi, WOFF2, CFF2 and variable fonts.
Images PNG, APNG, GIF, JPEG, WebP, BMP and ICO, animation included.
Media AV1, H.264 and VP9 video, audio and HLS streams.
SVG & Canvas SVG and the Canvas 2D context on hop’s own vector engine.
Storage Web Storage and IndexedDB.

Measured against test262 and the web-platform-tests.

hop for products

A browser engine for the thing you’re building.

hop’s engine is a library. Put a web view inside your app, device or kiosk — and keep it on a short leash.

  • Network allowlists — a view reaches only the hosts you name.
  • Budgets — script instructions and memory, set per view.
  • Crash isolation — a failing page ends only itself; nothing unwinds into your app.
  • Headless — render pages to PNG, text or layout, no window needed.

your_app.rs
let engine = Engine::builder()
.fetcher(Allowlist::offline(net).allow("docs.example.com"))
.jitless(true)
.build();
let host = EngineHost::inline(engine);
let view = host.open(Url::parse("https://docs.example.com/")?);
// a script and memory budget for this view
host.act(view, Act::Budgets(Budgets {
script: Some(50_000_000),
memory: Some(256 << 20),
}));
